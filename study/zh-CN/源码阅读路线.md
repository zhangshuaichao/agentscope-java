# 源码阅读路线

目标不是逐行背诵所有类，而是能解释一次调用、定位扩展点、判断状态和异常边界。以下顺序按当前提交组织。

## 第一轮：建立主干

### 1. 看懂 Agent 的契约

读 [Agent](../../agentscope-core/src/main/java/io/agentscope/core/agent/Agent.java)、[CallableAgent](../../agentscope-core/src/main/java/io/agentscope/core/agent/CallableAgent.java)、[StreamableAgent](../../agentscope-core/src/main/java/io/agentscope/core/agent/StreamableAgent.java)、[ObservableAgent](../../agentscope-core/src/main/java/io/agentscope/core/agent/ObservableAgent.java)。

验收：用自己的话解释“观察消息”“返回一个终结消息”“产生多个执行事件”的区别。

### 2. 理解数据形状

读 [Msg](../../agentscope-core/src/main/java/io/agentscope/core/message/Msg.java)、[ContentBlock](../../agentscope-core/src/main/java/io/agentscope/core/message/ContentBlock.java)、[ToolUseBlock](../../agentscope-core/src/main/java/io/agentscope/core/message/ToolUseBlock.java)、[ToolResultBlock](../../agentscope-core/src/main/java/io/agentscope/core/message/ToolResultBlock.java)。

练习：画出“用户提问 → 助手请求工具 → 工具结果 → 助手回答”的消息序列，标出哪两个对象需要通过调用 ID 关联。

### 3. 追一条最简单的 ReAct 路径

读 [ReActAgent](../../agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java)，按方法名搜索 `callInternal → buildAgentStream → doCall → CallExecution.doCallInner → coreAgent → executeIteration → reasoning`，再跟随输出处理进入 `acting` 或终结回答。不要第一天就顺序读完整个大类。

配套测试：[ReActAgentNewLoopReplyTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentNewLoopReplyTest.java)、[ReActAgentNewLoopE2ETest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentNewLoopE2ETest.java)。

验收：说明何时继续一轮、何时结束、工具结果怎样回到下一轮模型输入。实际停止条件以代码分支为准，不只记“有工具就循环”。

## 第二轮：理解可扩展性与边界

### 4. 模型与工具两个适配边界

读 [Model](../../agentscope-core/src/main/java/io/agentscope/core/model/Model.java)、[AgentTool](../../agentscope-core/src/main/java/io/agentscope/core/tool/AgentTool.java)、[Tool](../../agentscope-core/src/main/java/io/agentscope/core/tool/Tool.java)、[Toolkit](../../agentscope-core/src/main/java/io/agentscope/core/tool/Toolkit.java)。

练习：不接外部模型，先在纸上设计一个固定响应的 Model 测试替身和一个加法工具。区分工具的 schema 与输入参数实例；不要把真实密钥写进源码。

### 5. 中间件链

读 [MiddlewareBase](../../agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareBase.java) 和 [MiddlewareChain](../../agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareChain.java)。

配套测试：[ReActAgentMiddlewareIntegrationTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentMiddlewareIntegrationTest.java)。

练习：假设 A、B 两个中间件都在 next 前后记日志，手写执行顺序；再改变 order，预测结果。解释为什么“没有调用 next”可能短路后续执行。

### 6. 会话、状态与并发

读 [RuntimeContext](../../agentscope-core/src/main/java/io/agentscope/core/agent/RuntimeContext.java)、[AgentState](../../agentscope-core/src/main/java/io/agentscope/core/state/AgentState.java)。

配套测试：[AgentStateTest](../../agentscope-core/src/test/java/io/agentscope/core/state/AgentStateTest.java)、[ReActAgentPerSessionStateTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentPerSessionStateTest.java)。

练习：同一个用户的两个会话、同一会话的两次调用分别应该共享什么、隔离什么？为什么中间件应优先读取当前调用的状态，而不是共享 agent 字段？

### 7. 把不顺利的路径也走一遍

读工具权限、暂停、恢复和取消相关分支。配套测试：[ReActAgentHitlTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentHitlTest.java)、[ReActAgentInterruptToolCallTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentInterruptToolCallTest.java)、[ReActAgentReturnDirectTest](../../agentscope-core/src/test/java/io/agentscope/core/agent/ReActAgentReturnDirectTest.java)。

验收：解释工具被拒绝、等待人确认、执行途中取消这三种情况为什么不能都当作工具成功结果。

## 第三轮：走向工程化

读 [Harness 架构](../../docs/v2/zh/docs/harness/architecture.md)，再看 [HarnessAgent](../../agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java) 与具体中间件。先选择一项能力，例如上下文压缩或工作区，再沿配置 → 注册 → 拦截点 → 状态变化追踪，不要同时展开所有供应商扩展。

## 本地验证命令

仓库要求 JDK 17+ 和 Maven。下列是上游建议的验证方式，不表示本学习版已经执行成功：

```bash
# 核心模块及其依赖的测试
mvn -T1C -pl agentscope-core -am test
# 代码格式检查
mvn -T1C -pl agentscope-core -am spotless:check
# 仓库完整检查（更耗时）
mvn -B -T1C clean verify
```

首次构建需要解析依赖。使用测试替身学习时不必调用付费模型服务；不要在未确认配置的情况下运行需要真实外部服务的示例。验证结果和尚未完成的检查见 [翻译范围与验证](翻译范围与验证.md)。
